# stability-lens

**增量式算法的离散稳定性体检。** 给一个更新规则（或一串特征值）和一个步长，
直接告诉你 `η_max`、谱半径、判定结果与设计建议 —— 不用扫参，不用等实验发散。

```bash
$ stability-lens check --rule heavy-ball --beta 0.5 --lambda-max 2 --eta 2.25
-- Heavy-ball / momentum（λ_max = 2） -------------------------------------------
  判定: [ 缝隙 ]  连续稳定但离散不稳定（缝隙）：η 是上界的 1.500 倍

  β                      0.5
  λ_max                  2
  η_max = 2(1+β)/λ_max   1.5
  η                      2.25
  特征值 μ₁,₂            -0.1771 , -2.8229
  判别式 tr² − 4det      7（实根）
  ρ = max|μ|             2.8228757
  √β                     0.70710678
  ODE 阻尼 a = (1−β)/√η  0.333333  > 0 ⇒ ODE 无条件稳定
  离散性                 连续稳定 / 离散不稳定（缝隙）

  提示:
  · ODE 阻尼 a = 0.333333 > 0，连续时间无可争议地稳定；但离散迭代已越过单位圆。这就是「连续稳定 ⇒ 离散稳定」的构造性反例。
  · 注意：这**不是**因为 ODE 不稳定，而是因为前向 Euler 的绝对稳定域是有限的。
```

退出码 `2` = 缝隙。可以直接当作训练前的 gate：

```bash
stability-lens check --rule gd --spectrum "1,4" --eta 0.6 || echo "先降学习率或换格式"
```

---

## 为什么需要它

把增量式算法写成 ODE 只完成了一半。算法本身**就是**那个 ODE 的一个数值积分格式：

```
稳定性   =  Hurwitz(h 的 Jacobian)   ∩   积分格式的绝对稳定域(η)
```

前向 Euler 的绝对稳定域是以 `−1/η` 为圆心、半径 `1/η` 的**有限圆盘**，而 ODE 的稳定域是整个左半平面。
两者之间的缝隙就是"调小学习率也救不回来"之外的全部麻烦：连续时间稳定**不蕴含**离散稳定。

| 场景 | 步长上界 | 备注 |
|---|---|---|
| 前向 Euler（`x_{k+1} = (I+ηJ)x_k`） | `η_max = min 2(−Re λ)/\|λ\|²` | 实特征值特例 `2/λ_max`；复特征值分母是 `\|λ\|²` |
| 梯度下降（二次目标，`J = −A`） | `2/λ_max` | 病态 `κ = λ_max/λ_min` ⟺ 刚性 ODE |
| Heavy-ball / momentum | `2(1+β)/λ_max` | 动量把上界线性放大 `(1+β)` 倍，代价是振荡 |
| 任意 A-稳定格式（后向 Euler / proximal） | 无 | 无条件稳定，代价是每步解一个子问题 |
| 常步长 LMS 稳态方差 | `V = ησ²/(2−ηs²) ∝ η` | 噪声地板 `O(√η)`，与格式无关 |

## 安装与运行

**方式 A：免安装直接跑**（运行时零依赖，只要 Python ≥ 3.10）

```bash
cd stability-lens
python -m stability_lens check --rule gd --spectrum "1,4"
python -m stability_lens selftest
python -m unittest discover -s tests        # 145 项测试，纯标准库
python -m pytest tests -q                   # 同一套也可以用 pytest 跑
```

> 在受限沙箱/只读目录里，pytest 写缓存可能报警告或留下 `pytest-cache-files-*` 目录；
> 加 `-p no:cacheprovider` 即可完全避免。

**方式 B：正常安装**（需要 setuptools，即常规的 pip 环境）

```bash
pip install -e .                                                   # 本地开发
pip install git+https://github.com/OGAS19171976/stability-lens.git # 从 GitHub
pip install ".[numpy]"    # predict / monitor / transient / adaptive 需要 numpy
stability-lens check --rule heavy-ball --beta 0.9 --lambda-max 4
```

依赖是**分层**的：`core` / `diagnose` / `selftest` 零依赖，只用标准库；
`numpy` 支撑数值与在线监控；`torch` 只在 `torch_backend` 里需要
（双重反向传播算 HVP）。所以"装不上 torch"不会妨碍体检本身。

命令行输出会自动切到 UTF-8（Windows 的 GBK 控制台也不会因 `η`/`ρ` 崩掉）。

## Python API

```python
import stability_lens as sl

d = sl.diagnose_gd("1,4", eta=0.6)     # 曲率 λ(A) = {1, 4}，J = −A
d.eta_max      # 0.5
d.rho          # 1.4
d.stable       # False
d.exit_code    # 2  → 缝隙
sl.report.render(d)

# 只要上界，不判具体步长
sl.diagnose_heavy_ball(beta=0.9, lambda_max=4).eta_max       # 0.95

# 复特征值：λ = −1 ± 3i ⟹ η_max = 2·1/|λ|² = 0.2
sl.diagnose_euler("-1+3i,-1-3i").eta_max                      # 0.2

# 噪声地板
sl.diagnose_lms(eta=0.05).eta_max                             # 2.0 (=2/s²)
sl.steady_variance(0.05, 1.0, 1.0)                            # 0.025641

# Lyapunov 证书
sol = sl.solve_lyapunov_2x2([[-1, 0], [0, -4]], [[1, 0], [0, 1]])
sol.P, sol.positive_definite, sol.residual                    # diag(0.5, 0.125), True, 0.0

# JSON 输出（CI 友好）
import json; json.dumps(sl.to_json(d), ensure_ascii=False)
```

| 分组 | 主要 API |
|---|---|
| 线代 | `eig_2x2` `spectral_radius` `is_hurwitz` `solve_lyapunov_2x2` |
| 前向 Euler | `euler_eta_max` `euler_rho` `euler_stable` `euler_effective_rate` `bisect_eta_max` |
| 模拟 | `simulate_diagonal` `exact_flow_diagonal` `simulate_heavy_ball` `simulate_lms` |
| Heavy-ball | `heavy_ball_eta_max` `heavy_ball_eigs` `heavy_ball_rho` `heavy_ball_disc` `continuous_damping` |
| 体检 | `diagnose_euler` `diagnose_gd` `diagnose_heavy_ball` `diagnose_lms` `diagnose` `sweep_euler` `sweep_heavy_ball` |
| 噪声 | `steady_variance` `window_stats` |

> `--spectrum` 的约定：`--rule euler` 期望 **λ(J)**（稳定要求 `Re λ < 0`）；`--rule gd` 期望**曲率 λ(A) > 0**。
> 如果你给 euler 传了一串正实数，它会报"结构性不稳定"并提示改用 `--rule gd`。

## 退出码

| 码 | 含义 |
|---|---|
| `0` | 稳定，或只给出了上界建议 |
| `2` | **缝隙**（连续稳定但该步长下离散不稳定）或**瞬态放大**超阈值（`predict` 里也表示预测与实测不一致） |
| `3` | **结构性不稳定**：ODE 本身不稳定（`Re λ ≥ 0`），调步长无用 |
| `1` | 自检失败或未捕获异常 |
| `64` | 参数用法错误（如缺 `--spectrum`） |

## 真实训练上的预测（`predict`）

前向 Euler 的稳定域是**局部**判据：它在 `θ*` 附近成立，而 `λ_max` 在真实网络里算不出来
（Hessian 太大）。但 **Hessian-向量积**可以拿到，于是幂迭代就能估 `λ_max`：

```bash
stability-lens predict --quick                      # 合成数据，几秒
stability-lens predict --csv data.csv --hidden 16    # 真实宽表
```

真实数据（工作区数仓 demo 的订单宽表，n=1200，d=9，两层 tanh 网络 h=12，p=133，
weight decay 1e-3）上的实测输出：

```
  梯度对拍（解析 vs 中心差分）  7.68e-10
  Hessian 对称性 ‖H−Hᵀ‖/‖H‖   0.00e+00
  训练    阻尼牛顿 38 步 → loss=4.029e-01，‖∇L‖=2.872e-14（L2 = 0.001）
  局部极小检查  λ_min(H) = 4.4618e-04 → 严格局部极小 ✓

  λ_max：精确装配 5.62984527    幂迭代 5.62984527    相对误差 4.42e-13（154 步）
```

### 这套测量装置的三个坑（都实测踩过）

要在真实网络上把"实测边界"测准，比想象中难。这三条现在都写进了代码和测试：

| 坑 | 现象 | 修法 |
|---|---|---|
| **非线性饱和** | 扰动取 `1e-3` 时，`tanh` 饱和让距离停止增长，长窗口判据把发散误判成稳定 —— 实测边界偏 **145%** | 扰动压到 `1e-6`，测量停在线性区 |
| **残余梯度漂移** | `θ*` 处 `‖∇L‖ ≈ 1e-14` 仍有常数漂移；扰动衰减到同一量级后它主导读数，把增长率从 0.600 抬到 0.671 | **对称扰动** `θ* ± δ`，取 `‖θ⁺ − θ⁻‖/2`，漂移与偶阶项一起消掉 |
| **越界后的平坦区** | 越过 `η_max` 后轨迹逃到更平坦的区域，差值饱和，后半段斜率回落到 0.9975（把 ρ=1.535 的发散读成稳定） | 增长率取**前半段** log 距离的最小二乘斜率；扰动触底噪声地板则直接判稳定 |

另外两条设计上的必要动作：用**阻尼牛顿**（Cholesky 判正定 + Armijo 线搜索）把模型送到
严格局部极小（`λ_min > 0`），否则线性化判据本身不适用；`l2` 不能取太小（`1e-6` 时噪声方向上的
平坦谱会让牛顿迟迟不收敛、权重继续膨胀，`λ_max` 一路从 3.7 涨到 22.8）。

## 在线监控：发散前告警（`monitor`）

前面的东西回答"上界是多少"，`monitor` 回答**"现在这一版跑起来安不安全"**：

```bash
stability-lens monitor --quick          # 几秒
stability-lens monitor --steps 400      # 真实宽表
```

每到检查点，在当前 `θ_k` 上（**不是**只在 `θ*` 上）用**热启动幂迭代**估一次 `λ_max`，
得到当前的 `η_max(θ_k) = 2(1+β)/λ_max(θ_k)`；一旦 `η > η_max(θ_k)` 就告警。
它不需要事先知道最优解，也不需要等损失爆掉。

真实宽表上的实测（β=0，最多 400 步）：

```

linear   θ=0        0.5    0.51643      —     未爆      —    4.582e-01
linear   θ=0        0.9    0.929575     —     未爆      —    4.582e-01
linear   θ=0        1.01   1.04319      0      374     374    4.898e+00
linear   θ=0        1.3    1.34272      0       16      16    1.157e+157
mlp      随机初值    0.5    0.177625     —     未爆      —    4.478e-01
mlp      随机初值    1.3    0.461824     —     未爆      —    4.386e-01
mlp      θ*         0.9    0.319725     —     未爆      —    4.029e-01
mlp      θ*         1.3    0.461824     0     未爆      —    4.033e-01
```

**误报 0 次、漏报 0 次**：稳定配置全程沉默；所有真不稳定配置在**第 0 步**（最早可能）
就报警，二次目标上提前 374 步和 16 步。

### 两个只有真跑出来才知道的现象

1. **冷启动会把告警推迟。** 第一次检查没有可复用的特征向量，只能冷启动；若预算与热启动
   相同（8 次），Rayleigh 商偏低会让 `η_max` 被高估 —— 实测在线性模型上把告警从第 0 步
   推迟到了第 40 步。修法是首次检查给更大预算（默认 `max(power_iters, 60)`），
   并有一条回归测试盯着它。
2. **在 `θ*` 处算出的 `η_max` 在训练早期并不是约束。** MLP 从随机初值出发、
   `η = 1.3 × η_max(θ*)`，损失照样收敛到 0.4386（收敛值 0.4029）——
   因为早期 `λ_max(θ_k)` 明显小于 `λ_max(θ*)`，监控器据此**正确地**保持沉默。
   这说明"用最优点的界去卡整条轨迹"是保守的，而在线监控能说清保守在哪。
   （从 `θ*` 出发跑同一个 `η`，监控器立刻报警 —— 两组行放在一起才是完整故事。）

代价要说清楚：每次检查是 `2 × power_iters` 次梯度评估（FD 版 HVP）。
`check_every=20, power_iters=8` 约等于训练步数的 80% 额外开销 —— 它是**诊断模式**，
不是默认打开的东西。

## 非正规性的账：`ρ < 1` 也可能先放大（`transient`）

谱半径只管 `k → ∞`，而训练只跑有限步。非正规矩阵可以在 `ρ(M) < 1` 的前提下
先把误差放大若干倍再衰减 —— 这时候"ρ < 1 所以稳定"在实践中是误导的。

```bash
stability-lens transient --matrix "0.9,10;0,0.9"     # Jordan 块
stability-lens transient --example normal            # 正规矩阵对照
stability-lens check --rule heavy-ball --beta 0.9 --lambda-max 2 --eta 1.881
```

```
-- 非正规性 / 瞬态增长（Jordan 块 [[0.9,10],[0,0.9]]） --
  判定: [ 瞬态 ]  谱说衰减（ρ=0.9），实际先放大 38.7 倍（第 9 步）
  谱半径 ρ(M)            0.9
  瞬态峰值 max_k ‖M^k‖₂  38.7459（第 9 步）
  Kreiss 常数 K(M)       25.01
  σ_min((1+0i)I − M)     0.001
```

伪谱才是这件事的根源：在距特征值同样是 `0.1` 的地方，
正规矩阵的 `σ_min = 0.1`，而这个非正规矩阵只有 `0.001` —— **低了两个数量级**，
也就是"谱附近有一大片区域和特征值不可区分"，那一截正是瞬态增长的来源。

### 动量是这套框架里唯一的来源

`H` 是对称的，所以 `M = I − ηH` **正规**，`ρ < 1` 直接意味着误差单调下降 ——
纯 GD 永远不会有瞬态放大。真正的非正规性来自**动量的伴随矩阵**：

| β | η/η_max | ρ | **误差**峰值 `max_k‖e₁ᵀM^k‖` | 整状态峰值 `max_k‖M^k‖` | Kreiss |
|---|---|---|---|---|---|
| 0.0 | 0.99 | 0.9800 | **1.000** | 1.400 | 1.19 |
| 0.5 | 0.99 | 0.9356 | **1.898** | 2.673 | 1.87 |
| 0.9 | 0.90 | 0.9487 | **1.965** | 2.624 | 1.31 |
| 0.9 | 0.99 | 0.9487 | **4.961** | 6.976 | 3.58 |

**两列必须分开看**：`β = 0` 时整状态峰值报 1.40，但误差峰值恒为 **1.000** ——
前者只是"把二阶递推写成一阶状态"带来的表示假象。若只报状态范数，
就会给纯 GD 用户一个不存在的警告。所以 `check --rule heavy-ball` 两列都列出来，
而放大提示只看误差那一列。

`transient.py` 用 numpy 算任意 `n` 的精确 2-范数；`core.py` 另有一份**纯标准库的 2×2**
实现（保住零依赖）。两份独立代码在测试里逐位交叉验证（9 组配置，误差 < 1e-10）。

## Adam 的逐坐标界（`adaptive`）

自适应方法的更新是 `θ ← θ − η·P·∇L`，`P = diag(1/(√v̂ᵢ + ε))`。线性化后稳定条件是

```
η < 2 / λ_max(P·H)          P·H 与对称的 P^{1/2}·H·P^{1/2} 相似
```

所以只要在**预条件后的 HVP**（`w ↦ √p ⊙ (H(√p ⊙ w))`）上跑幂迭代就行 —— 这就是"逐坐标"的含义：

```bash
stability-lens adaptive --quick
stability-lens adaptive --eps 1e-8          # 真实宽表
```

真实宽表上的实测：

```
量                                     值
λ_max(H)（SGD 用）                      5.62984527
λ_max(P^{1/2} H P^{1/2})（Adam 用）     10.97457077

η_max  Adam/RMSProp                     0.182239
```

`v̂` 的**约定**必须说清楚，否则数字会差一个 `√n`：全批梯度是 `∇L = (1/n)Σᵢ ∂ℓᵢ/∂θ`，
而 Adam 的 `v̂` 建模成**单样本损失梯度**的二阶矩，所以不能除以 `n`。
（我第一版写成 `(f−y)/n` 就踩了这个坑，算出"Adam 的界紧 1850 倍"这种量纲错误的结论；
修正后是 **1.95 倍**，仍然有意义，但完全是另一个故事。）

另两点边界：`ε` 把预条件子上限钉在 `1/ε`（调小 ε 会让界更紧也更脆）；
本分析把更新当作 `−ηPg`，对应 `β₁ = 0`（RMSProp）—— `β₁ > 0` 时动量项还会引入
非正规性与瞬态放大（见上一节），那一情形下不给紧界。

## 接真实 PyTorch 模型（`torch_backend`，可选）

torch **不是依赖**：没有它时模块照样能 import，只有调用时才报一句人话。
接入不假设模型结构 —— 只要给出"重新算一遍损失的闭包"和参数列表：

```python
from stability_lens import torch_backend as tb

loss_fn = lambda: criterion(model(x), y)      # 标量、可微；每次调用重建计算图
params = [p for p in model.parameters() if p.requires_grad]

out = tb.eta_max_torch(loss_fn, params, beta=0.0)
print(out["lambda_max"], out["eta_max"])

d = tb.diagnose_torch(loss_fn, params, eta=3e-4, beta=0.9)   # 直接出判定
print(d.verdict)
```

Hessian-向量积用**双重反向传播**：`g = ∇L`（`create_graph=True`）后再求 `∇(g·v)`。
拿到 `λ_max` 之后下游全部复用已有模块 —— `η_max = 2(1+β)/λ_max`、动量瞬态放大、
退出码与 JSON 都自动就位，不需要为 torch 重写一遍。

```bash
pip install "stability-lens[torch]"
# 或指定 CPU 轮子源： pip install torch --index-url https://download.pytorch.org/whl/cpu
python -m pytest tests/test_torch_backend.py -v      # 有 torch 时自动跑，没有则 skip
```

装了 torch 的测试会对拍两件事：`λ_max` 与 `torch.autograd.functional.hessian`
算出的**精确** Hessian 顶特征值一致；以及 HVP 与梯度的中心差分一致。
（写这个测试时踩过一个坑：直接赋值 `p.data` 会切断 `flat → loss` 的计算图，
算出来的 Hessian 全是零 —— 正确做法是 `torch.func.functional_call`。）

## 设计说明

- **运行时零依赖**（core / diagnose / selftest 只用标准库）。只有 `predict`
  需要 numpy，且没装它会给出清晰提示，其余功能不受影响。
- **单一实现原则**：`simulate_lms` 只有纯 Python 一条路径（不做可选加速分支），
  保证"可复现的证据"只有一份口径。
- **蒙特卡洛的坑写进了 API**：`simulate_lms(..., x0=...)`。
  默认 `x0=1.0` 从 `e_0 = 1` 出发；做稳态估计请传 `x0=None`（从平稳分布抽样）。
  原因：初始条件的记忆以 `(1−ηs²)^k` 衰减，`η` 小时要 `~10/(ηs²)` 步才忘得掉 ——
  本项目实际踩过这个坑（`η = 0.01` 只烧 200 步会把稳态方差**高估 2.6 倍**，
  在双对数图上表现为斜率从 1 掉到 0.57）。`window_stats` 只给朴素标准误，
  它**忽略时间序列自相关、系统性偏小**；要置信区间请用 batch means 或 HAC。

## 已知边界

- 只覆盖**线性化后**的逐模态分析。非正规矩阵的瞬态增长（`ρ < 1` 却先放大）
  现在由 `transient` / `check --rule heavy-ball` 给出（见下文"非正规性的账"）；
  更大规模的非正规性仍建议配合伪谱图人工确认。
- 非光滑目标（ReLU / L1 / 投影）下 ODE 变成微分包含，需要 Clarke 广义梯度或单调算子理论。
- 大 `η`（`ηλ_max` 接近 2）正是 ODE 逼近失效的区间，此时结论只保证"趋势正确"。
- 只给均值场。要方差分布、置信区间、有限样本界，需要扩散逼近 / SDE。
